# 模型规划与版本迭代实施边界

用户已批准按全局审计的开发顺序继续实现。以下为在现有分层、会话运行时与人工确认门禁内的增量设计，Git 推送、公开发布与业务数据覆盖均不在当前动作范围。

## 模型规划

- 每次 interview / blueprint / task_graph 规划使用独立的现有配置助手会话；复用应用唯一 ConversationService。
- 领域通过 PlanningPort 调用，不依赖 CLI、Conversation 或 axum。模型结果来自规范化成功完整回合文本；禁止拿 backend_turn_id 匹配 app turn_id，禁止猜 stdout 或读取约定文件。
- 持久预约保存 owner/run/phase、幂等键、输入revision/hash、助手快照、conversation/app turn、状态、候选结果与错误。预约先落盘，副作用后发生；uncertain 不自动重发。
- 候选结果严格验证后仍需人工确认并 CAS 应用；未确认不能交接或执行。
- 规划费用按独立会话归入同一run，失败/取消/重试保留。Team执行预算必须包含规划费用；缺报告、未知价格或读取错误不能按零处理。

## 自适应任务

任务 schema v2 明确 execution_scope=task_workspace|project_integration 与 requirement_ids。只允许一张终结集成卡，依赖覆盖所有产物任务；中间测试不得因 type=test 获根目录集成权限。v1历史确认稿和执行收据继续兼容，不重写历史事实。

## 版本

产品与run分离，保存 parent_run_id / version_no / active_run / revision。每版本使用独立托管目录与Team/收据/账本；旧版本只读保留。

迭代只复制经过manifest列出的源码与入口说明，拒绝路径逃逸和越界symlink，排除凭证与运行数据库。版本回退选择已验收版本目录，不执行 git reset，不删除文件，不回写旧账目。

当前回退范围是代码版本选择；应用业务数据库的schema降级、数据回迁必须按具体产品设计，不能自动承诺。

## 验收

幂等双窗口只调用一次、断线/重启回读、候选写入未应用恢复、错误/空/截断JSON拒绝、不同产品不同问题与任务拓扑、CLI无强制网页卡、中间测试无集成权限、未确认不执行、全部规划/执行费用进同一预算、跨用户与CSRF、父版本不被改写、版本选择CAS与路径边界。

真实费用仍缺可核验费率来源。Fixture用于代码验证，不能写入真实验收账单。
