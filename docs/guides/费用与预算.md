# 费用与预算的当前行为

金额以 USD 表示，Token 与金额分开。账本不是提供商发票。

## 一条记录能说明什么

每次实际发送分别预约账本；同一逻辑回合的重试和技能续轮拥有独立 attempt。记录保留输入、输出、缓存读取、缓存写入 Token，并区分：

- `provider_report`：运行时返回的费用；Claude 的累计费用先转换为本回合增量。
- `configured_estimate`：用本机配置的精确模型费率估算，随记录保存价格、来源声明与更新时间快照。
- `legacy_unspecified`：升级前已有金额，原始来源未保存。
- `not_sent`：明确未调用后台的纯预约，保存零费用与原尝试 ID；实际发送但没有报告的记录不能归入此类。
- 金额为 `null`：未取得可用价格、缺缓存费率、计数无有效基线等。`cost_unknown_reason` 给出具体原因。

Codex 的最近请求用量仍用于上下文占用显示；费用账本使用原生累计计数计算各次发送的增量，包含该次发送内的多次模型请求。每个 attempt 保存独立基线，旧重复报告不能回退累计值；旧报告变更、计数回退或漏报边界将受影响费用标为未知，保留已测数量。有效累计值和不确定标记持久化，不靠重启或重新估价猜回金额。模型身份来自运行时确认，其他未核验运行时的估价保持未知。

升级前没有缓存分桶的记录继续保留空值，不以零补齐。启动不会自动用新价格改写历史金额。显式重估只接受有完整缓存分桶、尚无金额且计量边界有效的记录；CAS核对用户、attempt、模型、分桶及未知原因，保存新来源快照并保留已有金额。`billing_*` 不确定记录需额外对账，价格配置本身不能修复计量边界。

## 配置真实费率

在后端数据目录放置 `model-pricing.json`，或用 `AIONUI_MODEL_PRICING_FILE` 指向文件。模型 ID 必须与运行时记录精确一致。重启后对新回合生效。

结构如下（所有 `填入...` 都要替换；该模板故意不能作为有效价格配置）：

```json
{
  "version": 1,
  "source": "填入实际账户价格表或合同来源",
  "updated_at": "填入价格生效日期",
  "models": {
    "填入精确模型ID": {
      "input_usd_per_million": "填入数值",
      "output_usd_per_million": "填入数值",
      "input_includes_cached_tokens": true,
      "cached_read_usd_per_million": "填入数值",
      "cached_write_usd_per_million": "填入数值"
    }
  }
}
```

`input_includes_cached_tokens` 明确输入 Token 是否已经包含缓存分桶；有缓存时必须明确配置，不能靠默认值推测。输入包含缓存时会扣除缓存分桶后分别计价；缓存计数超过输入会保持费用未知。没有发生的缓存类型可不填费率，发生了却没有费率则保持未知。零费率只用于真实免费类别，不能作为未知价格的替代。

当前编码服务没有可核验价格表。回归测试中的 fixture 价格只用于检查算术和预算门禁，不代表实际费率。

## 预算门禁

- 无预算时可继续开发，费用仍可能未知。
- 已设预算时，记录费用达到上限或存在未知费用，拒绝新的实际 Send；自动重试和技能续轮也要重新检查。
- 规划与开发费用共同计入同一 Run 的预算。费用/预算读取失败始终阻断。
- 检查与预约在同一共享 ConversationService 内串行；不承诺跨后台进程原子性，也不代表提供商实时硬上限。已经开始的发送仍可能超支。
- 已完成或待审阅任务没有任何用量记录时，总费用保持未知。
- 交付检查会验证已设预算未耗尽；代码完成不能覆盖财务未通过项。

交付页成本下载是版本 2 JSON，包含规划和开发来源、任务汇总、app turn/attempt用量、缓存分桶、费用来源、价格快照与未知原因。尝试数量包括未调用历史，不等于模型调用次数。汇总未知金额仍为 `null`。报告应与提供商账单核对后用于实际付款判断。
