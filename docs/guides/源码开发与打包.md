# 源码开发与打包

当前开源仓库是包含 AionCore / AionUi 的单仓库。原上游双仓库文档作为通用参考；不要重新克隆上游 main 替换本分支。

## 开发运行

环境：Rust 1.95.0（AionCore/rust-toolchain.toml）、Node.js >=22 且 <25、Bun；原生模块编译可能需要 Python 3.11+、Xcode Command Line Tools 或对应平台编译工具。

```bash
git clone https://github.com/26YZT/speed-workbench.git
cd speed-workbench/AionCore
cargo build --locked --bin aioncore
cd ../AionUi
bun install --frozen-lockfile
AIONUI_BACKEND_BIN="../AionCore/target/debug/aioncore" bun run start
```

桌面开发启动会自行启动所选后端，无须另开同数据目录的 Core。编码助手 CLI 或模型服务需自行安装、登录并配置；源码不包含账号、密钥、模型额度和个人数据库。不要在不同实例之间共享临时 QA 数据目录。

## 编译前端与桌面分发的区别

- `bun run package` 是 Electron Vite 编译，产出 out/main、out/preload、out/renderer，不等于桌面安装包。
- `bun run dist` / build-with-builder 才进入后端准备和 Electron Builder 分发流程。
- 当前默认后端准备脚本使用上游 iOfficeAI/AionCore release。上游 binary 不保证有本分支产品工厂。
- `AIONUI_BACKEND_LOCAL_BINARY` 仅在下载失败后 fallback，不能用它保证选择本分支。

本分支桌面打包必须传入完整 `AIONUI_BACKEND_LOCAL_BUNDLE_DIR`，包含对应平台 binary 和全部 managed-resources。资源中包括平台运行时、内置工具/技能所需内容；单独 cargo build 不会生成完整分发资源。

```text
/absolute/path/to/speed-backend-bundle/
├── aioncore                  # Windows 对应 aioncore.exe
└── managed-resources/
```

bundle 应来自同平台的、已验证的本分支后端与完整资源准备流程，存放在 AionUi/resources/bundled-aioncore 目标目录之外。prepare 会删除该目标目录后复制，不能把源 bundle 指回目标。不要从个人配置或业务数据库凑资源，不要用上游 binary 替代本分支 binary。

Mac ARM 示例（先核对 bundle 内容）：

```bash
cd AionUi
AIONUI_BACKEND_LOCAL_BUNDLE_DIR="/absolute/path/to/speed-backend-bundle" \
  node scripts/build-with-builder.js arm64 --mac --arm64
```

不完整 bundle 当前可能警告后尝试上游 fallback；因此发布者必须检查准备结果为 sourceType=local-bundle、manifest 平台/架构，以及包中实际 aioncore 的 SHA256 等于指定本分支 binary。不能只凭进程退出 0 宣称本分支打包成功。平台 managed-resources 必须完整，通过准备脚本自身的 bundle 验证。

2026-10-06 R2 是维护者本机验收快照，其 out 包、运行资源和个人配置未纳入 Git。公开源码并不保证新编译器得到相同 binary SHA。本次开源不提供正式安装包，也没有完成 Developer ID、公证或新机器安装验收；不应从源码公开推断正式桌面分发已经完成。

## 验证

后端推送门禁依赖 just 和 cargo-nextest：

```bash
cd AionCore
just migration-check-test
just check
```

不安装 nextest 时，后端完整测试可用 `cargo test --workspace`；正式推送仍遵守 AGENTS.md 的 just 门禁。前端：

```bash
cd AionUi
just check
bun run test
```

根 .github/workflows/ci.yml 显式进入两个子目录，仅读取仓库并运行源码验证，不执行自动桌面发布、云部署或 GPT 评审。嵌套的上游 workflows 保留为历史/参考，不会被根仓库自动运行。

当前实际产品范围、费用未知与未验证路径见 [STATUS](../STATUS.md)。代码版本选择只处理代码路径，业务数据与运行服务应按具体应用约定处理。
