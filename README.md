# Speed Workbench

**AI 产品开发工作台 · 从产品想法到可运行的应用**

Speed Workbench 将需求梳理、产品规划、AI 编码、任务审核和版本迭代整合到一个工作空间。输入你的产品想法，围绕同一份方案推进开发，让需求、任务、代码与交付结果保持关联。

开发与维护：[26YZT](https://github.com/26YZT) · [使用文档](docs/guides/源码开发与打包.md) · [问题反馈](https://github.com/26YZT/speed-workbench/issues)

## 为产品开发而设计

- **把想法变成方案**：通过需求访谈明确目标用户、核心问题、功能范围和约束，形成产品蓝图。
- **把方案变成任务**：将需求拆解为带依赖关系和验收标准的开发任务，清晰安排执行顺序。
- **把任务变成代码**：连接你配置的模型与编码助手，在项目工作目录中执行开发。
- **让迭代有据可循**：审核任务结果，记录调用用量，保存代码版本，继续下一轮开发。

## 核心能力

| 能力 | 使用方式 |
| --- | --- |
| AI 需求访谈 | 围绕产品目标生成问题，补充需求信息，确认产品方向 |
| 产品蓝图 | 整理目标用户、核心流程、功能模块和可追踪需求 |
| 任务规划 | 生成开发任务、依赖关系和验收标准，支持编辑与确认 |
| AI 开发执行 | 使用已配置的编码助手执行任务，查看执行记录和产物 |
| 人工审核 | 对照验收标准检查结果，提交审核意见、返工或继续开发 |
| 用量管理 | 汇总规划与开发的模型调用、Token 用量和计价信息 |
| 代码版本 | 保存代码快照，在独立工作目录创建新版本，保留迭代关系 |

## 工作流程

**输入想法 → 需求访谈 → 确认蓝图与任务 → AI 开发 → 审核交付 → 版本迭代**

1. **创建产品**：填写产品名称、目标用户、解决的问题、预期输出和约束。
2. **梳理需求**：回答需求访谈问题，补充关键场景，确认产品蓝图。
3. **确认任务**：检查任务拆解、依赖关系和验收标准，确定开发方案。
4. **启动开发**：选择编码助手和工作目录，执行开发任务。
5. **审核结果**：查看任务产物与执行记录，决定通过、返工或继续。
6. **推进迭代**：保存选定代码的版本快照，以新的工作版本继续完善产品。

你负责产品方向和关键决策，AI 参与规划与编码，工作台负责组织流程、记录执行和管理代码版本。

## 适用场景

- **AI 应用**：需求摘要、内容整理和接入模型服务的业务工具。
- **管理工具**：事项管理、信息录入、查询和本地数据管理。
- **数据处理**：CSV 汇总、报表生成和命令行工具。
- **产品迭代**：围绕已有代码版本完善功能，形成新的工作版本。

## 快速开始

### 环境准备

| 工具 | 要求 |
| --- | --- |
| Rust | 1.95.0，仓库已固定工具链 |
| Node.js | 22～24 |
| Bun | 用于依赖安装和开发启动 |
| 编码助手与模型服务 | 本机可用，并完成相应配置 |

编译原生依赖时，还需要 Python 3.11+ 和对应平台的编译工具。

### 安装与启动

在 macOS / Linux 上执行：

```bash
git clone https://github.com/26YZT/speed-workbench.git
cd speed-workbench/AionCore
cargo build --locked --bin aioncore

cd ../AionUi
bun install --frozen-lockfile
AIONUI_BACKEND_BIN="../AionCore/target/debug/aioncore" bun run start
```

`AIONUI_BACKEND_BIN` 指向本仓库编译的后端。启动工作台后，配置模型与编码助手，在「产品工厂」中创建你的第一个产品。

更多环境配置和桌面打包方式，见 [源码开发与打包](docs/guides/源码开发与打包.md)。

## 从一个具体想法开始

```text
产品名称：需求摘要助手
目标用户：需要整理访谈记录的产品经理
解决的问题：访谈资料分散，需求提取和归类耗时
产品想法：输入访谈文本，生成摘要、需求列表和待确认问题
预期输出：可本地运行的 Web 应用
约束条件：使用已配置的模型服务，支持保存与查询历史结果
```

在工作台中补充这些信息，再确认蓝图与任务，即可围绕同一个产品目标推进开发、审核和迭代。
